## Decisions so far

- [Inspigo For Business: capture project detail, challenges, and problems solved](tickets/01-inspigo-for-business-detail.md) — Before: hardcoded per-client builds, unsustainable once several clients signed close together with their own revisions. Hard problem: config drives component composition/layout, not just theme/copy. Solo-designed the architecture with 1 backend engineer. ~350 client orgs, ~100 users/client (~35k end users). Screenshots at `apps/portfolio/public/project/ifb/`.
- [Inspigo AI: capture project detail, challenges, and problems solved](tickets/02-inspigo-ai-detail.md) — RAG via CMS upload → S3 → Pinecone (chunking/metadata) with OpenAI embeddings; OpenAI primary model, Bedrock fallback; WebSocket (legacy roleplay) + SSE (newer) streaming. Hard problem: scaling to concurrent users. Owned frontend/streaming UX + markdown rendering + CMS interface. 5-person team, peak thousands of chats/day. Screenshots at `apps/portfolio/public/project/inspigo-ai/`.
- [Inspigo — n8n pentest automation workflow: capture project detail, challenges, and problems solved](tickets/11-inspigo-n8n-automation-detail.md) — Weekly scheduled scan of production: SCA/SAST (Semgrep, pnpm audit) + DAST (Nuclei, OWASP ZAP), AI-formatted (OpenAI) into an OWASP-standard report, converted to PDF, delivered to Rocket.Chat. Requested by the engineering manager. Hard problems: no authenticated-route scanning yet (headers only), and microservice sprawl multiplies scan surface. Screenshot at `apps/portfolio/public/project/automation/pentest.png`. Split off the AI call-center copilot into ticket 21.
- [Inspigo — AI call-center agent copilot: capture project detail, challenges, and problems solved](tickets/21-inspigo-ai-callcenter-copilot-detail.md) — OpenAI live transcription + per-case knowledge table drives checklist/evaluation. Hard problems: AI-vs-human scoring margin of error >5 on subjective rubric dimensions; transcription accuracy (agent/customer voice separation, background noise). Product team's idea, built with 2 product-team members. Covers all ~11 agents; automates 100% session scoring vs. the prior ~10%-sample manual QA. Screenshot at `apps/portfolio/public/project/automation/copilot.png`.
- [Inspigo — CI/CD using GitHub Actions: capture project detail, challenges, and problems solved](tickets/12-inspigo-cicd-detail.md) — Security audit, typecheck & test, and build+deploy pipelines; no CI existed before, still only on a handful of projects. Deliberately scoped to run on the production branch + version tags only, not every push. Solo-built, brainstormed with AI. Impact: faster builds, push-to-deploy instead of manual `pm2` SSH work, automatic audit/test on serverless targets. No dedicated evidence artifact yet (the referenced `workflow.yml` turned out to belong to ticket 11).
- [Inspigo — project documentation using Storybook: capture project detail, challenges, and problems solved](tickets/13-inspigo-storybook-detail.md) — Documents the shared cross-app design system/component library only. Hard problem (unsolved): keeping stories in sync with real components — maintenance lost out, Storybook here has since gone stale/unmaintained. Own initiative, solo. Covers nearly all cross-app shared components, especially small primitives. Not presentable outside Inspigo. Site copy should frame this as past-tense ("built X"), not as an ongoing practice.
- [Inspigo — AWS S3 media upload, Amplify, and Vercel deployment: capture project detail, challenges, and problems solved](tickets/14-inspigo-cloud-infra-detail.md) — S3 upload via presigned URLs (direct) and a backend-proxied path with a Lambda image converter/optimizer. Amplify for hosting/deploy; all projects migrated off Vercel onto Amplify. Hard problem: Amplify deploys take 6–10 min with manual cache management, worse than Vercel's automatic caching. Collective initiative (EM + team). Impact: better media organization than DB-stored media, easier image optimization. Screenshots at `apps/portfolio/public/project/aws/`.

- [Inspigo — Admin dashboard (charts, monitoring, statistics for clients): capture project detail, challenges, and problems solved](tickets/16-inspigo-admin-dashboard-detail.md) — Custom admin panel covering member management, org management, member stats, and a learning-path module; built on RHF+Zod and Recharts. Hard problem: permissions/roles, since the backend authz model is a JWT-attached scope system rather than a role table. Built with the product team + a dedicated backend engineer. Adoption: went from nothing to near-universal — almost every client org uses it, ~2 admins/org. Screenshot at `apps/portfolio/public/project/admin-dashboard/`.

- [Inspigo — CMS (forms, media upload): capture project detail, challenges, and problems solved](tickets/15-inspigo-cms-detail.md) — Full-CRUD CMS spanning every Inspigo content type: podcast audio, video, IFB dynamic UI config, learning paths, AI roleplay content, payment/voucher/credit. Built on RHF + shadcn + Zod, TanStack Table for lists. Hard problem: normalizing inconsistent error and response/list shapes across many backend services. Built with a team. Impact: other teams self-serve product content updates without going through engineering. Screenshots at `apps/portfolio/public/project/cms/`.

- [Inspigo — video player: capture project detail, challenges, and problems solved](tickets/17-inspigo-video-player-detail.md) — Wraps `react-player`; HLS adaptive streaming, playback speed and quality control. Hard problem: wiring up analytics initially. Inherited from a legacy developer rather than greenfield. Powers all Inspigo video content and is a shared module reused across platforms (Inspigo For Business, Inspigo AI). Screenshots at `apps/portfolio/public/project/video-player/`.

- [Inspigo — analytics/tracking (Google Tag Manager, Google Analytics, MoEngage): capture project detail, challenges, and problems solved](tickets/18-inspigo-analytics-tracking-detail.md) — GA + Facebook Pixel routed through GTM; MoEngage for campaign triggering; user-journey tracking via MoEngage + in-house `inspigo-telemetry`.
